# 한글 타자 연습기 (Hangul Typing Tutor) — 설계 문서

작성일: 2026-06-25

## 1. 개요

한글 **글자는 알지만 키보드 자판 위치는 모르는 외국인**이, 두벌식 자판에서 각 자음/모음이 어느 키에 있는지 손가락 위치를 단계적으로 익히는 웹 기반 타자 연습기.

- **핵심 목적:** 키보드 자판(두벌식) 위치 익히기 — "다음에 누를 키"를 가상 키보드 위에서 손가락 색으로 짚어줌
- **대상:** 한글 글자(ㄱ, ㅏ 등)와 소리는 알지만 QWERTY 위 자판 위치를 모르는 학습자
- **연습 구조:** 단계형 레슨 (기초 자음 → 기초 모음 → 자모 조합 → 단어 → 짧은 문장)

### 결정적 제약

대상이 "한국어 키보드를 설치/설정하지 않은 외국인"이라는 점이 모든 설계를 좌우한다. 따라서 OS 한글 IME에 의존하지 않고, **영문 QWERTY 입력을 우리가 직접 두벌식 자모로 매핑·조합**한다. 사용자는 한글 키보드를 설치할 필요가 없다.

## 2. 기술 스택

- **Next.js (App Router) + TypeScript**
- **Tailwind CSS** — 스타일링
- **es-hangul** — 자모 조합/분해 라이브러리. 그 위에 키 입력 자동자(automaton)를 얇게 얹는다
- **localStorage** — 진행률 저장 (MVP 단계 백엔드/DB 없음)
- **Vercel** — 정적 배포
- **Vitest + React Testing Library** — 테스트

## 3. 화면

연습 화면은 **키보드 중심형** 레이아웃을 채택한다.

- 칠 대상 텍스트(완료/현재/남은 글자 구분 표시)
- 크게 표시되는 가상 두벌식 키보드 — 다음에 누를 키를 파란색으로 강조
- 색 코드: **왼손 = 자음(주황), 오른손 = 모음(초록)** → "왼손 자음 / 오른손 모음"이 자연스럽게 학습됨
- 다음 키 힌트: "press R (ㄱ) · 검지"
- 타수(타/분)·정확도·레슨 진행률 표시

페이지 구성:

- `/` — 홈: 레슨 목록 + 진행률, 시작/이어하기
- `/lesson/[id]` — 연습 화면 (Keyboard + TypingLine + StatsBar)
- 레슨 완료 결과는 별도 페이지 없이 오버레이로 표시

## 4. 모듈 구조

각 단위는 한 가지 역할만 가지며, 잘 정의된 인터페이스로 통신하고 독립적으로 테스트 가능하게 설계한다.

### 순수 로직 (React 무관, 단위 테스트 대상)

| 모듈 | 역할 | 의존성 |
|------|------|--------|
| `lib/keyboard/dubeolsik.ts` | 키맵: 물리 키 → `{ jamo, hand, finger, type('consonant'\|'vowel'), shift? }`. **키보드 렌더링과 조합이 공유하는 단일 출처** | 없음 |
| `lib/hangul/composer.ts` | 조합 자동자: 현재 조합 상태 + 들어온 자모 → 다음 상태 + 확정 텍스트. es-hangul을 감쌈 | es-hangul |
| `lib/curriculum/lessons.ts` | 레슨 데이터(순서·단계·목표 문자) | 없음 |
| `lib/progress/store.ts` | 진행률 저장/복원 (인터페이스 + localStorage 구현체) | 없음 |

### React 계층

- **`useLessonSession` 훅** — 한 레슨 진행 오케스트레이션: 키 입력 캡처 → composer 투입 → 기대값과 비교 → 타수·정확도·완료 추적. 뷰 상태 반환
- **컴포넌트**
  - `Keyboard` — 키맵으로 두벌식 레이아웃 렌더, 다음 키 + 손가락 색 강조, shift 상태 표시
  - `TypingLine` — 완료 / 현재 / 남은 글자 렌더
  - `StatsBar` — 타수·정확도·진행률
  - `NextKeyHint` — "press R (ㄱ) · 검지"

## 5. 핵심 데이터 흐름

```
keydown 이벤트
  → event.code(물리 키 "KeyR") 사용              ← event.key 아님이 핵심
  → 키맵 조회 → 자모 획득
  → composer가 조합 블록 갱신
  → 기대 글자와 비교 → 타수/정확도 갱신
  → 글자 완성 시 다음 글자로
  → 레슨 완료 시 결과 저장 후 오버레이 표시
```

**핵심 트릭:** `event.key`가 아닌 **`event.code`**(물리 키 위치)를 사용한다. 이로써 사용자 OS 자판 설정과 무관하게 동작하고, 브라우저 IME를 건드리지 않는다(`preventDefault`). 이것이 "한글 키보드 설치 불필요"를 가능하게 하는 메커니즘이다. 키 캡처는 포커스된 컨테이너에서 수행한다.

## 6. 커리큘럼 (MVP)

단계당 3~5레슨.

1. **기초 자음** — 홈로우 우선: ㅁㄴㅇㄹㅎ → ㅂㅈㄷㄱㅅ → ㅋㅌㅊㅍ
2. **기초 모음** — ㅏㅓㅗㅜㅡㅣ → ㅑㅕㅛㅠㅐㅔ
3. **자모 조합** — 가·나·고·무 등 단순 CV 음절
4. **단어** — 한국·사람·안녕 등
5. **짧은 문장** — 안녕하세요·한국어 배우기 등

## 7. 에러 처리

- **오타:** 키/글자 빨간 플래시 + 오류 카운트, 다음으로 넘어가지 않음 (타자 연습기 관례)
- **es-hangul 엣지케이스:** composer는 순수 함수로, 알려진 시퀀스에 대해 단위 테스트로 검증
- **localStorage 비활성(시크릿 모드 등):** try/catch로 graceful degradation — 연습은 정상 동작, 저장만 생략
- **SSR:** 키 리스너·스토리지는 클라이언트에서만 (`'use client'`, `useEffect`)

## 9. 확장 이음새 (Extension Seams)

지금 기능을 만들지는 않되(YAGNI), 나중에 갈아엎지 않고 끼워넣을 수 있도록 이음새를 미리 둔다.

### 9.1 쌍자음·복합모음 — "데이터 추가"로 끝남

- composer를 처음부터 **es-hangul 위에** 올리므로 조합 엔진은 ㄲ·ㅘ·겹받침 등 모든 자모를 이미 안다. 엔진 변경 불필요
- `dubeolsik.ts` 키맵 스키마에 **`shift` 필드를 처음부터 포함** → 쌍자음(ㄲㅃㄸㅆㅉ)·ㅒㅖ는 키맵에 shift 항목만 채우면 됨
- 입력 캡처에서 `event.shiftKey`만 읽으면 됨
- 복합모음 ㅘ(ㅗ+ㅏ) 등은 두 키를 순서대로 치면 composer가 합성 → 사실상 공짜로 동작
- **결론:** 쌍자음 확장 = 키맵 데이터 + shift 플래그 + 커리큘럼 레슨 추가. 아키텍처 변경 없음

### 9.2 랭킹/DB — 이음새 3개로 드롭인

1. **`ProgressStore`를 인터페이스로 정의하고 시그니처를 async(Promise)로 둔다**
   - MVP 구현체는 `LocalProgressStore`(동기 localStorage를 Promise로 감쌈)
   - 나중에 `ApiProgressStore`(fetch 기반)로 **교체만** 하면 호출부 변경 0
   - Next.js App Router는 Route Handler(`app/api/.../route.ts`)·Server Action이 기본 내장 → 서버 추가가 자연스러움. Vercel Postgres/Supabase를 나중에 붙여도 프론트 재구조화 불필요

2. **`LessonResult` 타입을 공용 계약으로 고정** — `{ lessonId, wpm, accuracy, completedAt }`
   - 지금은 이 레코드를 localStorage에 저장, 나중엔 같은 모양 그대로 API로 POST → 랭킹 테이블이 소비. "결과 레코드"가 미래 DB와의 계약

3. **익명 `userId`(uuid)를 첫 실행에 발급해 localStorage에 보관**
   - 랭킹은 점수를 누군가에게 귀속시켜야 함. 익명 id를 처음부터 두면, 나중에 로그인 도입 시 "기존 점수 이어받기"도 가능

4. `composer`·`keymap`·`curriculum`을 UI·스토리지와 분리된 **순수 모듈**로 유지 → 나중에 서버가 결과를 검증하거나 레슨을 내려줄 때 그대로 재사용 가능

## 10. 범위 밖 (YAGNI for MVP)

- 계정 / 클라우드 동기화 / DB
- 쌍자음·일부 복합모음(shift 레이어) — 후속 단계 (단, 이음새는 9.1대로 준비)
- 랭킹 / 리더보드 — 후속 단계 (단, 이음새는 9.2대로 준비)
- 소리 / TTS, 로마자 툴팁 (대상이 글자는 이미 앎)
- 멀티플레이어
